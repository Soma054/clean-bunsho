2026年11月18日 · @naena
概要
AIが生成した文章やWebからコピーした文章に混ざる「見えない文字」（ゼロ幅スペース、特殊な空白、書字方向の制御文字など）を、Macで手間なく取り除く常駐アプリ「くりーんぶんしょ」（GitHub のリポジトリ名は clean-bunsho）を作る。ブラウザ版の「見えない文字クリーナー」で検証した処理ロジックをそのまま引き継ぐ。
ヒアリングで決まったこと：
• 対象：まずMac。Windowsは Mac版の完成後に着手
• 利用者：自分と身内だけ。GitHub で公開し、そこから入手してもらう
• 使い方：4つの方法をすべて用意し、アプリ内の設定で選べるようにする
• 開発：Claudeがコードまで作る
対象環境と配布
第1段階はMac版のみ。身内に配るため GitHub で公開し、そこからダウンロードしてもらう。

補足：
• 自動監視はパスワード管理アプリからのコピーを無視する（秘密情報を示す印が付いたデータは触らない）
• どのモードでも、文字を消したときは「3個を削除しました」などの通知を出せる（設定でオフ可）
• 何も見つからなかったときはクリップボードを書き換えない（文字の書式を壊さないため）
• メニューバーのメニューから「きれいにする」を選んだときは、きれいにするだけで貼り付けはしない（どのアプリに貼るかがはっきりしないため）
ショートカットの決まり：
• 既定のキーは ⌃⌥⌘V。Finder の ⌥⌘V（ファイルを移動）との重なりを避けるために選んだ
• 初回起動時に登録を試み、他のアプリが先に使っていて登録できないときは「未設定」にして、設定画面でそのことを知らせる
• 後から他のアプリが同じキーを登録した場合や、アプリ内のメニューのキーとの重なりは検出できない。そのときは設定でキーを変えてもらう
• 押したあとは、既定ではきれいにして自動で貼り付ける。初回に「アクセシビリティ」の許可を求める。設定で「きれいにするだけ」に変えられる

1.  メニューバーのメニュー：「クリップボードをきれいにする」「ウィンドウを開く」「自動監視 オン/オフ」「設定…」「終了」
2.  クリーナーウィンドウ：ブラウザ版と同じ構成（左に入力、右に結果、内訳、見えない文字の表示）
3.  設定ウィンドウ：下の3つのタブ

技術構成
Swift（SwiftUI）で作る Mac 専用アプリに決定。右クリックメニュー（サービス）や自動貼り付けなど Mac の機能をそのまま使え、アプリも軽い。

良い点
気になる点
Swift / SwiftUI（採用）
4モードすべて素直に実現できる。サイズ数MB

Tauri（Web技術＋Rust）
ブラウザ版の画面と処理を流用でき、Windows 版も同じコードで作れる
右クリックメニュー（サービス）は Mac 向けの追加実装が必要
Electron
情報が多く作りやすい
アプリが100MB前後と重い。常駐アプリには不向き
Windows 版で処理の結果をそろえるため、処理ルールとテスト用の文章・期待する結果を JSON ファイルにまとめ、両方のアプリで同じテストを通す。
ビルドについて：Claude がソースコード一式と手順書を用意する。ビルドは GitHub Actions（GitHub が用意する macOS 26 の Mac）で行うことに決定。テスト、ビルド、アドホック署名、.dmg 作成まで自動で進み、v で始まるタグを push すると Releases に公開される。手元の Mac は macOS 26.5.2 のままでよく、Xcode は不要。
公開と更新
新しい版は、v で始まるタグを付けて push するだけで公開される。
1.  処理ルールを変えるときは、先に Tests/CleanBunshoCoreTests/Fixtures/cases.json にテストケース（入力・期待する結果・削除数・置換数）を足す
2.  main に push すると、GitHub Actions でテストとビルドが走る。できた .dmg は Actions の各実行の「Artifacts」から試せる
3.  問題なければ git tag v0.1.0 → git push origin v0.1.0 で Releases に公開される
使う人が新しい版に入れ替えたときは、アドホック署名が版ごとに変わるため、アクセシビリティの許可を一度消して付け直す必要がある。手順は README と Releases の説明に書く。
